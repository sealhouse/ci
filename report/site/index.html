    Per fork, latest

    Current carries

    The commits each fork keeps on top of upstream, which every sync replays, as of the latest report. Carries stay; drops are regenerated or dropped once upstream has them; upstream PRs are picked early, each with a carries.lock line in ci; one to look at has merged, closed or changed upstream since it was carried, or its line removes or replaces it. A sync keeps only the newest ci pin, so pins above one are left over from before the fork's last sync.

    Every carry

    Library replaces

    The fork library releases ci's replaces.lock puts in place of upstream's modules, as of the latest report. Each fork's go.mod that requires the module should replace it with the line's release; the replaces pull requests do this. A line can go once upstream has a plain release that meets its drop condition: a version, or a release tag holding the upstream PR's merge.
